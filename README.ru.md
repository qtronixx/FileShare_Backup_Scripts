# Invoke-MirrorBackup

Скрипт резервного копирования/одностороннего зеркалирования (Robocopy) с гибкой
классификацией ошибок и оповещением в Telegram. Один скрипт обслуживает произвольное
количество независимых задач (файловые шары, каталоги с дампами БД и т.п.) — настройки
задачи задаются отдельным конфигом, без изменения кода.

## Возможности

- Одностороннее зеркалирование (`/MIR`) источника в приёмник с многопоточностью (`/MT`).
- Классификация результата: **УСПЕХ / ВНИМАНИЕ / КРИТИЧЕСКИЙ СБОЙ** — не только по коду
  возврата Robocopy (сумма битовых флагов), но и по анализу лога на HEX-коды критических
  ошибок Win32 (например, отказ в доступе), даже если итоговый код возврата некритичен.
- Уведомления в Telegram на старте, при успехе, предупреждении и критическом сбое, с
  ретраями и таймаутом на случай недоступности Telegram.
- Настройки задачи полностью вынесены в `.psd1`-конфиги: общие (Telegram, коды ошибок,
  ретеншн логов) — в `common.psd1`, специфичные для задачи (источник/приёмник,
  исключения) — в `tasks/*.psd1`. Задача может переопределить любое общее поле.
- Unicode-лог Robocopy (`/UNILOG:`) — корректно пишет кириллические имена файлов и путей
  независимо от кодовой страницы консоли.
- Защита от параллельного запуска одной и той же задачи (именованный Mutex на задачу —
  разные задачи друг другу не мешают и могут выполняться одновременно).
- Проверка доступности источника и свободного места на диске назначения перед стартом.
- Автоматическая ротация старых логов.
- Режим `-DryRun` (эквивалент `/L` в Robocopy) — показывает, что было бы сделано, без
  реальных изменений.

## Структура репозитория

```
.
├── Invoke-MirrorBackup.ps1   # единственный скрипт
├── common.psd1.example       # шаблон общего конфига (без секрета) — коммитится в git
├── common.psd1               # реальный конфиг с токеном — НЕ коммитится (см. .gitignore)
├── .gitignore
└── tasks/
    ├── share01.psd1          # пример: файловая шара
    └── sql01.psd1            # пример: каталог с бэкапами БД
```

## Требования

- Windows Server / Windows с PowerShell 5.1+ и Robocopy (входит в состав ОС).
- Доменная или локальная сервисная учётная запись с правами на чтение источника(ов) и
  запись в приёмник(и), от имени которой будет выполняться задание планировщика.
- Бот в Telegram (создаётся через [@BotFather](https://t.me/BotFather)) и chat_id канала/
  чата, куда он добавлен как участник.

## Быстрый старт

1. Скопируйте `Invoke-MirrorBackup.ps1` и папку `tasks/` на сервер, например в
   `C:\Scripts`.
2. Скопируйте `common.psd1.example` в `common.psd1` рядом со скриптом и впишите
   реальные `BotToken` и `ChatId`.
3. Ограничьте доступ к папке скрипта (в `common.psd1` хранится токен открытым текстом,
   единственная защита — NTFS-права):
   ```powershell
   icacls "C:\Scripts" /inheritance:r /grant:r "SYSTEM:(OI)(CI)F" "BUILTIN\Administrators:(OI)(CI)F"
   ```
4. Отредактируйте (или добавьте новый) файл в `tasks/` под свою задачу — см. раздел
   [Конфигурация задачи](#конфигурация-задачи).
5. Проверьте вхолостую, ничего не копируя и не удаляя:
   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Invoke-MirrorBackup.ps1 -ConfigPath C:\Scripts\tasks\share01.psd1 -DryRun
   ```
   и посмотрите лог в папке, указанной в `LogDir` конфига задачи.
6. Уберите `-DryRun` и добавьте в планировщик заданий по одной задаче на каждый `.psd1`:
   ```
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Invoke-MirrorBackup.ps1 -ConfigPath C:\Scripts\tasks\share01.psd1
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File C:\Scripts\Invoke-MirrorBackup.ps1 -ConfigPath C:\Scripts\tasks\sql01.psd1
   ```
   Запускать задание нужно от той же сервисной учётной записи с нужными правами доступа.

## Конфигурация

Итоговая конфигурация собирается в порядке возрастания приоритета:
**встроенные значения по умолчанию → `common.psd1` → конфиг задачи (`-ConfigPath`)**.
Любое поле из `common.psd1` можно точечно переопределить в конкретной задаче.

### common.psd1 — общее для всех задач

| Поле                           | Назначение                                                                 |
|--------------------------------|-----------------------------------------------------------------------------|
| `BotToken`                     | Токен Telegram-бота.                                                        |
| `ChatId`                       | ID чата/канала для уведомлений.                                             |
| `MessageThreadId`              | ID топика (если чат с топиками). Можно переопределить в задаче.            |
| `Threads`                      | Значение для `/MT:N` Robocopy.                                              |
| `NonCriticalExitCodes`         | Коды возврата Robocopy, не считающиеся сами по себе критичными.            |
| `CriticalErrorHexCodes`        | HEX-коды Win32-ошибок в логе (например, `0x00000005`), повышающие статус до "ВНИМАНИЕ" даже при некритичном коде возврата. |
| `TreatCopiedFailuresAsWarning` | Если `$true` — установленный бит `8` в коде возврата (часть файлов не скопирована) всегда даёт статус "ВНИМАНИЕ", а не тихий "УСПЕХ". |
| `LogRetentionDays`             | Сколько дней хранить старые логи перед автоудалением.                       |
| `MinFreeSpaceGB`               | Порог свободного места на диске назначения для предупреждения.             |

### tasks/*.psd1 — специфичное для задачи

| Поле            | Назначение                                                              |
|------------------|--------------------------------------------------------------------------|
| `TaskName`       | Название задачи — используется в логах, имени Mutex и сообщениях Telegram. Обязательно. |
| `Source`         | Источник копирования (UNC-путь или локальный). Обязательно.             |
| `Destination`    | Приёмник копирования. Обязательно.                                       |
| `LogDir`         | Папка для логов этой задачи. Обязательно.                                |
| `LogFilePrefix`  | Префикс имени лог-файла. Обязательно.                                    |
| `CopyAcls`       | `$true` — добавляет `/SEC` (сохранение прав NTFS источника). Для файловых шар обычно `$true`, для каталогов с дампами БД — `$false`. |
| `ExcludedFiles`  | Список шаблонов файлов для `/XF`.                                        |
| `ExcludedDirs`   | Список шаблонов каталогов для `/XD`.                                     |
| `MessageThreadId`| (опционально) свой топик Telegram для этой задачи, если отличается от общего. |

## Логика оповещений

| Условие                                                                                   | Статус            |
|--------------------------------------------------------------------------------------------|--------------------|
| Код возврата **не** входит в `NonCriticalExitCodes`                                        | 🚨 КРИТИЧЕСКИЙ СБОЙ |
| Код возврата в `NonCriticalExitCodes`, но в логе найден один из `CriticalErrorHexCodes`     | ⚠️ ВНИМАНИЕ         |
| Код возврата в `NonCriticalExitCodes`, установлен бит 8 (часть файлов не скопирована) и `TreatCopiedFailuresAsWarning = $true` | ⚠️ ВНИМАНИЕ |
| Код возврата в `NonCriticalExitCodes`, критических HEX-кодов не найдено, бита 8 нет (или `TreatCopiedFailuresAsWarning = $false`) | ✅ УСПЕХ |

Коды возврата Robocopy — сумма битовых флагов (см. [документацию Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/robocopy)):
`0` — нет файлов для копирования; `1` — файлы скопированы; `2` — обнаружены лишние файлы/каталоги в приёмнике; `4` — обнаружены несовпадения; `8` — часть файлов/каталогов не скопирована; `16` — серьёзная ошибка, ничего не скопировано.

## Безопасность

- Токен Telegram хранится в `common.psd1` открытым текстом осознанно: ценность токена
  ограничена правами бота (может писать только в чаты, где уже состоит), поэтому при
  компрометации сервера достаточно отозвать его у @BotFather и выпустить новый.
  Единственная реальная защита — NTFS-права на папку скрипта (см. выше).
- `common.psd1` **не должен** попадать в git — коммитьте только `common.psd1.example`
  (уже учтено в `.gitignore`).
- Конфиги парсятся через `Import-PowerShellDataFile`, который понимает только литералы
  (хэш-таблицы/строки/массивы/числа) и не может исполнить произвольный код — в отличие
  от дот-сорсинга обычного `.ps1` в качестве конфига.

## Устранение неполадок

- **"Файл конфигурации не найден"** — проверьте путь в `-ConfigPath` и наличие
  `common.psd1` рядом со скриптом (или передайте `-CommonConfigPath` явно).
- **"Источник недоступен"** — проверьте доступность UNC-пути и права сервисной учётной
  записи, от имени которой выполняется задание.
- **Задача сразу завершается с кодом 2** — предыдущий запуск этой же задачи ещё не
  закончился (сработала защита от параллельного запуска). Разные задачи друг на друга
  не влияют.
- **Уведомления в Telegram не приходят** — проверьте `BotToken`/`ChatId` в конфиге,
  добавлен ли бот в чат, и загляните в лог задачи — ошибки отправки логируются с деталями
  ответа Telegram API.
- Кириллица в логе выглядит как кракозябры — не должно происходить благодаря
  `/UNILOG:`; если всё же случилось, откройте лог явно как `Get-Content -Encoding Unicode`.
